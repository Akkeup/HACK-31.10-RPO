# Локальная база знаний и существующий датасет флагов

Первый этап frontend: mock knowledge/questions/countries/players, синтетические flags и country, никаких реальных данных не нужно. Для backend: локальный content pack и PostgreSQL, import источников отдельно до LAN игры. Реальный flag dataset уже есть, его поля/пути в этом чате не предоставлены; adapter mapping заполняется после инспекции исходника, ничего не скачивать повторно.

Production: sources сохраняют точный URL/revision/retrievedAt/license/localPath/SHA256; facts ссылаются на источники; книги/модули/contentVersion; вопросы с family/sourceIDs/private answerKey/explanation; страны с aliases/flagAssetId и проверенными фактами. draft→reviewed→published; только опубликованные используются в игре. Импорт повторяемый, старые pinned версии неизменяемы. Corpus должен покрывать вопросы, один current факт/мини-тема на небольшой chunk. Полная библиотека не помещается в prompt модели и не выдаётся клиенту.

Начальные источники для отдельной подготовки: Arithmetic https://en.wikibooks.org/wiki/Arithmetic ; CS Unplugged https://www.csunplugged.org/en/at-home/ ; World History https://en.wikibooks.org/wiki/World_History ; исторические источники https://ru.wikipedia.org/wiki/Исторический_источник ; хронология https://ru.wikipedia.org/wiki/Хронология ; Wikidata https://www.wikidata.org/wiki/Wikidata:Database_download . Сохранять атрибуцию/условия конкретного источника. Здесь эти источники не скачивались заново и не утверждается, что содержимое fixtures получено из них. Флаги берутся из существующего набора команды с его provenance.

LLM на backend: получает выбранные короткие локальные факты/задание, возвращает structured draft, backend проверяет схему и ссылки, человек/проверенные правила утверждают содержание. Валидная схема не гарантирует истинность. Генерация не хранит историю игрока. Для MVP заранее подготовить опубликованный банк, при таймауте использовать фиксированный материал. Нет облачной модели и удалённого поиска во время игры.

Instruction для country teacher: «Ты преподаватель читального зала. По COUNTRY_FACTS составь ровно3–4 коротких предложения на русском, максимум80 слов. Назови страну/географическое положение; столицу только если однозначна в фактах; добавь1–2 подтверждённых факта. Флаг описывай только по переданной записи. Не придумывай символику, статистику, даты. Если фактов мало, status=insufficient_data. Верни status, descriptionSentences, usedFactIds. Не добавляй списки и вступления». Черновик валидируется/проверяется до публикации, сохраняется и не генерируется при каждом визите.

country.description публично содержит3–4 строки-предложения и factIds. Проверка sentence count должна анализировать реальный текст, не только длину массива: без сокращений/внутренних нескольких предложений в строке. Runtime отдаёт уже проверенный текст. Closed aliases/правильный countryId не попадают в flag question; asset path/hash без названия, SVG sanitized/без внешних ресурсов или PNG. Сохранять пропорции. Визуально неоднозначные flags исключать/уточнять.

Демо-pack flags-demo намеренно содержит только одну страну и один family, повторённый для демонстрации UI. Это отрицательный semantic fixture для publish: полноценный production test5 разных family он не поддерживает. Не раздувать банк перефразированием/новыми ID. При недостатке вопросов запуск production проверки отклоняется. Библиотека и реальные модели/флаги не считаются подготовленными этим ZIP.
