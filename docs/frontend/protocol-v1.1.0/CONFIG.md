# Конфигурации и admin editor

JSON Schema по отдельности: render-config, character-visual-config, world-config, character-config, npc-behavior-config. config.schema.json задаёт publicDocument и adminDocument с revision. Все значения обязательны; schema defaults не подставляются автоматически. Рабочие значения по умолчанию лежат в fixtures/http/*-config.json и admin-put.json.

Локальные RenderConfig и CharacterVisualConfig: качество, дальность, тени, LOD, pixelRatio, экспозиция, анимации, выбор разрешённой модели, визуальный масштаб, скорость анимаций, имена и материалы. Обычный игрок может менять их только локально после валидации. В браузере можно сохранить именно эти небольшие настройки, без bearer/контента мира. Сброс восстанавливает серверные defaults. modelScale влияет только на визуальное отображение; коллизия и расстояния на сервере независимы. modelId берётся из разрешённого опубликованного каталога, не из URL введённого пользователем. Изменение вида не увеличивает серверную скорость.

WorldConfig: размеры сетки и чанков, spawn, activeChunkIds, placements объектов, npcIds, время/погода, decorDensity, interestRadiusChunks и maxResidentChunks. CharacterConfig: скорости, runMultiplier, radius, разрешённые действия и фиксированные частоты симуляции. NPCBehaviorConfig: личности, тема, сложность, знания, адаптация, память, локальный provider и timeout/fallback. Эти параметры меняет только admin через защищённый API. public config исключает world.placements, activeChunkIds, npcIds и весь npcBehavior; скрытые знания, память и настройки provider не выдаются игроку. Публичные NPC-поля приходят в snapshot.

Редактор: GET /api/v1/admin/worlds/{worldId}/config → 200 с ETag "config-1". Редактировать копию values, валидировать локально. PUT полного adminValues с If-Match: "config-1" → 200 новый adminDocument с revision=2 и ETag "config-2". Это replacement, не JSON Patch/merge patch. Нет If-Match — 428 CONFIG_CONFLICT; ревизия устарела — 412 CONFIG_CONFLICT. Нельзя автоматически перезаписывать чужие изменения: загрузить актуальную копию и показать конфликт. При потере ответа выполнить GET и сравнить values/revision, а не повторять с новой revision вслепую.

Backend повторно проверяет schema, role и межполевые условия: grid min≤max, chunkSize power of two, worldId совпадает с path, spawn в активном проходимом чанке, все activeChunkIds существуют и не повторяются, placements и npcIds уникальны и разрешимы, модель доступна, объект находится в своём чанке, профили NPC уникальны и соответствуют миру, knowledgePack существует локально, rules имеет пустой modelName, ollama имеет заранее установленную модель. interestRadius/maxResident не могут порождать обязательный набор свыше B; chunkSize/grid/placements должны соответствовать опубликованному контентному каталогу. Локальные пути, скрипты, произвольные LLM URL и секреты в конфиг не принимаются.

Горячие параметры: renderDefaults, characterVisualDefaults, timeOfDayHours, weather, decorDensity; walkSpeedMps, runMultiplier, interactionRadiusM, allowedActions, maxInputSilenceMs; difficulty/personality/timeout/memory/provider известных NPC и лимиты очереди. Они применяются атомарно на следующем серверном тике после транзакции PostgreSQL. Backend последовательно шлёт config.changed до snapshot нового tick. Старые defaults не перезаписывают сделанные игроком локальные графические настройки; новый обязательный серверный лимит применяется всегда. NPC уже в обработке использует снимок старой revision, новые запросы — новую.

Структурные параметры: worldId/worldRevision, chunkSize/grid/spawn/activeChunkIds/placements/npcIds, collisionRadius, interestRadius/maxResident, набор NPC и modelId/knowledgePack, а также фиксированные частоты. Изменение требует остановленных комнат и нового заранее валидированного контентного выпуска. При активной или ожидающей комнате PUT возвращает 409 RESTART_REQUIRED целиком, без частичного применения; при отсутствии комнат backend разрешает только значения, соответствующие уже установленному каталогу новой worldRevision. Админ API не генерирует 3D-файлы: новый набор контента публикует серверный разработчик/оператор до PUT. Если каталог не установлен — 422 INVALID_REQUEST. В v1 изменение частот вообще запрещено схемой.

Аудит сохраняет actorUserId, старую/новую revision, diff, timestamp, requestId; секретов в diff быть не должно. Транзакция конфигурации плюс transactional outbox гарантирует, что committed revision будет применена/объявлена после перезапуска; при пропуске события клиент видит configRevision в snapshot и выполняет GET public config, временно приостанавливая предсказание. Конфигурация не считается успешной до commit. В server.error/debug запрещено возвращать закрытый adminValues обычному игроку.
