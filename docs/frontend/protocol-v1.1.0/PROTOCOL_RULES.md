# Версии и совместимость

Версия текущего контракта: 1.1.0. HTTP major prefix: /api/v1. WebSocket subprotocol: discovery.v1. Каждое JSON-сообщение имеет точное protocolVersion="1.1.0". До выдачи ticket клиент получает bootstrap.protocolVersions и выбирает поддерживаемую точную версию. Ticket связывается с этой версией. Сервер 1.0.0 не обязан принимать 1.1.0 или 1.0.1, пока не объявил их поддержку; нельзя молча переключать версию в рамках соединения.

SemVer: PATCH исправляет документацию/инструменты и сохраняет допустимый набор wire-данных; MINOR добавляет заранее согласованные поля, типы событий и возможности с новыми схемами и явным выбором версии; MAJOR меняет значения полей, удаляет поля, меняет единицы, алгоритм бюджета или семантику действий. Уже выпущенные schemas/v1.0.0 не перезаписываются: новые версии кладутся рядом. Поля revision конфигурации и worldRevision контента независимы от версии протокола. serverInstanceId меняется при перезапуске процесса и не является счётчиком ревизии.

JSON-объекты закрыты additionalProperties=false; неизвестные поля, типы и enum отклоняются. extensions — единственная предусмотренная область дополнений с ключами x-*. Дополнения не должны менять авторизацию, физику или результаты игры, ограничены общим размером сообщения. Клиент не игнорирует неизвестное обязательное событие: фиксирует VERSION_UNSUPPORTED и переподключается после bootstrap. Это строгое согласование, а не обещание автоматической совместимости по major.

JSON: UTF-8, без BOM, NaN, Infinity и повторных ключей. Целые числа ≤2^53−1; сервер не выдаёт Rust u64 за этим пределом. UUID передаются строками; в примерах фиксированные UUID не являются секретами. Timestamp — RFC3339 UTC, миллисекунды допускаются. Время симуляции определяется tick, не часами клиента. Клиент не использует своё время для ограничения скорости.

Форматы проверяются до исполнения. Межполевые проверки (бюджет, grid, ссылки на модели, нормализация вектора, If-Match, роли) выполняются отдельно и описаны в docs. В Rust применять Serde deny_unknown_fields, конечные числа и ограничение body до десериализации. В JavaScript использовать Ajv2020 + ajv-formats, регистрируя все schemas по $id; готовый пример в tools/validate.cjs. Автоматическое преобразование типов, проставление defaults и удаление неизвестных полей запрещены.

Порядок изменения: предложение с wire-примерами → согласование обоих владельцев → новая папка схем → позитивные и негативные fixtures → проверки → новая версия ZIP → одновременно объявленная поддержка на обеих сторонах. Добавление поля в строгую схему текущей версии без выпуска версии запрещено.


Выпуск1.1: точное HTTP-согласование и migration описаны в docs/MIGRATION_1.1.md. Старые schemas/v1.0.0 неизменяемы. MINOR расширяет согласованные данные только внутри явно выбранной версии; old clients не получают новые payload автоматически.
