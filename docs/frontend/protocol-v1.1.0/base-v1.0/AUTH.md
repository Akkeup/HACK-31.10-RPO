# Auth и LAN TLS

В v1 локальная учётная запись username/password. Нет OAuth, email, обязательного интернета и открытой регистрации. Оператор до игры создаёт 2–5 player и отдельного admin через локальный серверный CLI/seed; CLI не является публичным API. Пароли хешируются Argon2id с индивидуальной солью; сырые пароли и токены не журналируются. Серверный seed задаётся отдельно, пароли из fixtures никогда не становятся production-паролями.

POST /auth/login выдаёт криптографически случайный opaque bearer token с энтропией не менее 256 бит на 3600 секунд. Сервер хранит хеш токена, userId, role, expiry и revoke state. Токен хранится только в памяти браузера, не в URL, localStorage и IndexedDB. Обновления token в v1 нет: после expiry повторный login. При истечении или отзыве токена сервер закрывает связанные сокеты кодом 4003; 401 TOKEN_EXPIRED или UNAUTHORIZED для HTTP. Logout отзывает текущий токен, а не все входы аккаунта.

WSS auth выполняется ДО upgrade. Браузер получает ticket через защищённый POST /sessions/{id}/ws-ticket. Ticket одноразовый, случайный, 30 секунд, связан с userId/token/sessionId/точной protocolVersion и точным разрешённым Origin. Backend проверяет членство и роль из токена. Browser WebSocket API не предоставляет произвольный заголовок Authorization, поэтому используется `wss://<origin>/api/v1/ws?ticket=...` с subprotocol discovery.v1. Не передавать access token в query.

При upgrade сервер атомарно потребляет ticket, проверяет TTL, актуальность access token, Origin allowlist, session membership и Sec-WebSocket-Protocol; при неудаче возвращает 401/403/409/426 до 101. Ticket считается потреблённым при успешном переходе к upgrade; при сетевой неопределённости клиент получает новый ticket. Origin отсутствует или не совпадает — 403 FORBIDDEN, даже если ticket валиден. Для CLI/mock клиентов явно передать тот же Origin. subprotocol отсутствует/неверен — 426 VERSION_UNSUPPORTED; версия ticket не поддерживается — 409 VERSION_UNSUPPORTED. client.hello — handshake формата приложения, не аутентификация.

Backend и прокси ДОЛЖНЫ исключать query ticket из access/error logs, tracing, аналитики и истории диагностики. Ticket не сохраняется браузером, отправляется один раз, не пересылается в Referer (Referrer-Policy:no-referrer). Не сохранять Authorization и содержимое password. Если невозможно гарантировать фильтрацию, отключить access logging маршрута /api/v1/ws.

LAN production имеет один HTTPS origin для HTML, JS, ассетов и API. Caddy завершает TLS и проксирует WSS в Axum на внутреннем HTTP; прямой порт Axum, PostgreSQL, Ollama не публикуется в LAN. TLS 1.2+; сертификат с SAN фактического DNS-имени/IP. Локальный CA заранее добавляется в доверие каждого клиентского устройства и браузера. Нельзя отключать проверку TLS или рассчитывать, что браузер WSS примет недоверенный self-signed сертификат. Нет публичного ACME на офлайн-запуске.

Same-origin снимает необходимость разрешающего CORS; даже так WS Origin проверяется отдельно. Cookie auth отсутствует, поэтому клиент использует bearer и credentials:omit. Admin-роль проверяется сервером при каждом GET/PUT admin; скрытая кнопка интерфейса не является проверкой прав. После смены роли сервер отзывает старые токены администратора. Ответы NPC/имена выводятся textContent, без HTML и выполнения скриптов.
