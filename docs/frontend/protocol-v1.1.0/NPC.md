# NPC interactions и локальный AI

Основной provider v1 — детерминированные правила и локальный knowledge pack. Ollama — необязательная внутренняя замена, не отдельный публичный API. Облако и интернет не нужны. Публичные NPC идентифицируются npcId, профили server-only содержат личность, предмет, difficulty, память и fallback.

Игрок после active session и world.ready отправляет npc.interact с requestId UUID, npcId, talk/inspect и text≤2000. Сервер проверяет allowedActions, принадлежность NPC текущему interest, connected/ready, серверное евклидово расстояние до NPC ≤interactionRadiusM и доступную линию взаимодействия по коллизиям. Игрок не передаёт позицию, свой userId, награду, системный prompt или знания. В waiting/paused ответ 409-equivalent CONFLICT без запуска AI.

Один pending запрос на игрока. Частота ≤1/2с/player; очередь ограничена maxQueue, одновременно выполняется maxConcurrent (1–2). Сервер сохраняет pending и snapshot context, отправляет npc.accepted с status=pending. Контекст: собственный прогресс, ограниченная memory этого NPC+player, безопасный профиль и local knowledge. Глобальная память других игроков в запрос не попадает. Срок обработки от accepted до terminal ограничен profile.timeoutMs, включая время очереди; переполнение — NPC_BUSY retryable, не принимая работу.

Результат npc.result отправляется только владельцу requestId. status completed содержит plain text, source rules/ollama/fallback, knowledgeIds и текущую progressRevision; failed имеет error и source=none; cancelled — text пуст, source=none, error=null. Сервер проверяет output≤4000, допустимые knowledgeIds и не выполняет команды из текста LLM. Учебные достижения присваиваются только серверными правилами проверки/наблюдения, не фразой модели и не произвольным knowledgeId из её ответа.

На timeout, недоступную модель или некорректный output вернуть детерминированный fallbackText с source=fallback, без новых knowledgeIds. Это completed и не ложный успешный ответ AI. NPC_TIMEOUT используется для технической failed-операции, если даже fallback невозможен; ошибка не добавляет прогресс. UI показывает итоговый ответ после завершения, token streaming в v1 отсутствует. Смену состояния NPC talking/idling другие игроки могут увидеть в snapshot, но текст/память приватны.

Идемпотентность хранится в PostgreSQL: ключ (userId,sessionId,requestId), канонический payload hash и terminal result. Повтор идентичного pending возвращает npc.accepted без повторного задания; повтор terminal — npc.result с тем же interaction. Тот же ID с иным payload — REQUEST_ID_REUSED. Хранение результата 24ч, никакие автоматические повторы с новым UUID не допускаются. При commit результата изменения learning_progress, npc_memory и terminal response атомарны. Уникальный ключ награды предотвращает повторное начисление после crash/retry. Восстановленные после аварии pending запускаются снова безопасно либо завершаются fallback; потерянный WS не отменяет принятый запрос.

npc.cancel {targetRequestId} относится только к своему запросу. Если pending, атомарно установить cancelled, отменить доступную задачу и отправить npc.cancelled, коррелируя с requestId команды cancel. Если terminal уже committed, вернуть npc.result с фактическим terminal result, коррелируя с командой cancel; прогресс назад не откатывается. Неизвестный/чужой target — NOT_FOUND. Если результат и отмена гоняются, первая committed terminal запись выигрывает. GET /sessions/{id}/interactions/{requestId} восстанавливает статус даже после reconnect/истечения membership; авторизация по владельцу записи.

Память привязана к userId/worldId/npcId, ограничена memoryTurns и memoryTtlHours; очищается по TTL оператором/фоновой задачей. Для difficulty=adaptive правила выбирают сложность по completedKnowledgeIds и последним ответам этого игрока; simple/advanced фиксируют уровень. Долговременный прогресс отдельный от истории диалогов. Внутренний интерфейс provider: input {profileRevision, npcId, userContext, knowledgeContext, text, deadline}, output {plainText, candidateKnowledgeIds, source}; candidate проверяет игровая логика. Этот интерфейс внутренний, не wire-контракт с браузером.
