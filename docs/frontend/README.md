# Discovery — браузерный клиент

JavaScript ES modules, Three.js, Vite, HTML/CSS, GLB/glTF, WebSocket, JSON Schema 2020-12. Реализован по переданному **Discovery Protocol 1.1.0**. Rust, PostgreSQL, Compose и реализация AI не изменялись. Уже существовавшее изменение корневого README оставлено нетронутым.

## Запуск без Rust и без внешнего интернета

Нужен Node.js 22.12+. Зависимости устанавливаются заранее:

```sh
cd apps/client
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Vite поднимает локальный mock HTTP/WebSocket на том же origin. Демо-вход игрока автоматический; Мира и Алекс — синтетические участники. «Мир / Поведение → Войти как демо-администратор» выполняет настоящий mock `/api/v1/auth/login`, смену членства и новое WS-подключение. Демо-аккаунты `explorer` и `admin`, пароль `discovery-demo` применяются **только локальным mock**, не являются seed или учётными данными Rust.

```sh
npm test
npm run test:integration
npm run build
npm run preview
```

Preview: http://127.0.0.1:4173. В mock-режиме для preview нужны исходный checkout, assets и установленные dev-зависимости: mock не включён в `dist`. При реальном развёртывании `dist` обслуживает локальный HTTPS origin вместе с Rust API. `file://` не поддерживается.

После установки npm-зависимостей игра не обращается к внешним сайтам, CDN, облачному AI или шрифтам. Локальный HTTP/WS сервер нужен и без интернета. Service worker кеширует **только исполняемую оболочку**, аутентификация и мир в дисковый кеш не попадают. После потери локального сервера существующая сцена может остаться видимой, но движение и диалог требуют серверных подтверждений; автономный обход серверных правил не предусмотрен.

## Управление

Вид от первого лица. Щелчок в сцене — Pointer Lock, мышь — yaw/pitch; WASD / стрелки — движение относительно взгляда. E при наведении на ближний стол — занять место; E на NPC — изучение/проверка. После сворачивания панели щёлкните в сцене для продолжения обзора. Esc закрывает урок/опрос через сервер и возвращает управление. В соревновании Esc только сворачивает панель; F — встать. «Найти Софию» поворачивает взгляд к NPC. Во время загрузки interest сервер замораживает движение до world.ready. Сенсорное управление перемещением пока не добавлено; мобильная проверка относится к вёрстке, а основной ввод рассчитан на ноутбук с мышью/клавиатурой.

## Настройки и права

- **Графика**: официальный RenderConfig и CharacterVisualConfig. Пресеты low/medium/high, дальность, pixel ratio, тени, LOD, анимации, экспозиция, модели из разрешённого текущего interest, визуальный масштаб, скорость анимации, имена, materialStyle и реакции. Применяются сразу, валидируются, сохраняются только эти небольшие настройки в localStorage. Сброс восстанавливает текущие серверные renderDefaults/characterVisualDefaults. Некорректное хранилище заменяется defaults.
- **Мир**: администратор получает полный adminDocument через защищённый API, редактирует время, погоду, плотность и placements. У игрока только публичные параметры; placements, activeChunkIds и NPC knowledge/provider не выдаются. Структурные правки в активной комнате целиком отклоняются RESTART_REQUIRED — редактор это объясняет.
- **Поведение**: администратор редактирует серверные параметры персонажей и профилей NPC: скорость/радиус, характер, тему, сложность, память, timeout/fallback. Исполнение и повторная проверка остаются серверу. Данные provider/knowledge pack только отображаются администратору; клиент не вызывает AI.

Admin PUT отправляет полные adminValues с точным ETag/If-Match. 412/428 показывают конфликт и предлагают GET, без автоматической перезаписи. Кнопка «Отменить правки» возвращает последнюю загруженную серверную копию; общего endpoint заводского сброса в v1 нет. Серверные изменения применяются по config.changed/effectiveTick перед соответствующим snapshot, без затирания пользовательской графики.

Переключатели видимости моделей и сетки мини-карты — временные настройки представления, не дополнительные wire-поля RenderConfig. Они принимают только boolean и не меняют геометрию коллизий, роли или прогресс.

## Сеть

Одна реализация DiscoveryAdapter работает с mock и Rust: bootstrap → login → public config/manifest → create/join session → одноразовый ws-ticket → discovery.v1 → hello/welcome → interest/resources → ready/snapshot. Bearer только в памяти; credentials:omit; ticket одноразово в WS URL; логи URL/ticket клиент не создаёт. Полные исходящие и входящие envelopes проверяются официальными неизменёнными схемами через Ajv2020 + ajv-formats. Дубликаты JSON-ключей, BOM и сообщения свыше 64 KiB отклоняются. Счётчики serverSeq/inputSeq и конфигурационные ревизии независимы.

Ввод ≤20 Гц, серверная симуляция mock — 20 Гц, снимки — 10 Гц. Положение своего персонажа сглаживается по серверным координатам, другие игроки интерполируются с задержкой 120 мс без неограниченной экстраполяции. Локальное предсказание физики не используется. В waiting/paused реальный сервер определяет отсутствие движения. Heartbeat 10 с; reconnect с новым ticket и сбросом последовательности; pending NPC восстанавливается GET по исходному requestId, без автоматического нового UUID. Закрытие диалога отправляет npc.cancel.

Текст NPC/имена выводятся через textContent. Прогресс не присваивается за локальную отметку интерфейса. Дневник явно отличает отметку текущего сеанса от серверного прогресса.

## Нормативный ресурсный бюджет

`W = manifest.totalWorldBytes`, `B = floor(W / 10)`. На **каждой операции** сумма byteSize уникальных SHA-256 в resident и reserved не превышает B. Это общий предел активных моделей, неактивного LRU и загрузок, не 10% RAM. Один hash имеет одну запись, reservation и запрос; общий GLB разделяется экземплярами, освобождение возможно только после удаления всех ссылок.

Клиент принимает только полный world.interest сервера. Дальность графики не создаёт запросов дополнительных чанков. До fetch резервируется byteSize, загрузок одновременно не больше двух. Отмена освобождает резерв после завершения очистки запроса. Проверяются фактические байты, SHA-256, chunk JSON Schema, world/revision/coordinates/ID и зависимости. Внешние glTF URI разрешены только через выделенные ресурсы interest или встроенный data URI. Повреждённый файл повторяется не более одного раза.

Дополнительный счётчик оценивает RAM/VRAM ресурсов и экземпляров с лимитом 256 МиБ. Он включает буферы, геометрию, материалы, текстуры и экземпляры; это консервативная оценка, не точный замер памяти драйвера/всего браузера. Декодирование текстур резервирует консервативный запас; сложный набор может быть отклонён раньше фактического исчерпания памяти. При давлении снижается pixel ratio. UI показывает логический бюджет и отдельную оценку памяти.

При смене interest старые экземпляры удаляются, refcounts освобождаются, доступные hash переиспользуются. При LRU-выгрузке вызываются dispose геометрий, материалов, текстур, skeleton и ImageBitmap; ссылки/буферы очищаются. При смене worldRevision старый мир сначала полностью освобождается. world/API всегда cache:no-store; SW, CacheStorage, IndexedDB и disk cache не используются для world resources. Полный каталог остаётся в Node mock и не включается в браузерную сборку.

## Художественный demo-мир

100 реальных пространственных чанков лесопаркового кампуса с GLB, двумя моделями исследователя, площадью, павильоном и обсерваторией. Каждая модель/геометрия мира — опубликованный бюджетируемый ресурс; художественная сцена не спрятана в JS/UI или service worker. Генераторы находятся в scripts и исполняются только при публикации; runtime загружает GLB через interest. У деревьев два опубликованных геометрических LOD. Полный каталог `assets/world/catalog.server-only.json` служит только mock-серверу.

```sh
npm run world:publish
```

После публикации перезапустить mock. Скрипт пересчитывает SHA-256/W/B, проверяет single-chunk closure и удаляет собственные неиспользуемые ресурсные файлы. Смена опубликованного реального мира требует версии каталога и серверного процесса публикации, а не admin PUT из клиента.

## Проверки

`npm test`: официальные позитивные/негативные fixtures, byte-identical схемы архива, строгие конфигурации, storage recovery, JSON limits, интерполяция, дедупликация C∪R, refcount/LRU, физический предел, реальные hash/byteSize всего опубликованного контента, точный W/B и пригодность каждого чанка.

`npm run test:integration`: полный цикл соревнования, настоящий обрыв WS и восстановление, отмена/возврат, новый матч без автоматической ставки, lesson/quiz lifecycle, затем локальный HTTP/WS на случайном порту, bearer/ticket/subprotocol, последовательность событий, готовность, реальные fetch/SHA/GLB decode, запрет ресурсов вне interest, движение по серверным тикам, NPC accepted/result, права, ETag/412 и RESTART_REQUIRED.

`/?qa=1` в Vite DEV — браузерные проверки сцены, ввода, настроек, моделей, прав, диалога, серверных сохранений и перехода interest с замером frame time. QA-код удаляется из production build. `window.discovery.diagnostics()` предоставляет только копию последних показателей; управляющие объекты и токены не экспортируются.

Реальный Rust backend и ноутбуки всех участников в этой среде недоступны. Успех mock/схем не доказывает живую Rust-интеграцию, TLS и одинаковую производительность на целевых машинах. Остаточные ограничения mock описаны в transport.md.

Актуальные результаты и границы проверки 1.1.0: [competition.md](competition.md). Старые замеры 1.0.0 не относятся к новой камере и столу.
