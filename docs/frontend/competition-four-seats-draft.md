# Проект изменения: стол соревнований на четыре места

Статус: **проект по запросу пользователя, ещё не выпущенная спецификация**.
База — Discovery Protocol 2.0.0. Выпущенные схемы в
`apps/client/src/protocol/v2.0.0` не изменены, Rust/SQL/Docker не менялись.

## Что уже работает в демо

- Новый `gaming-table-5ca9d5.glb`: 1.8×1.2 м, высота 0.76 м, 76 244 байта.
  Оригинал/хеш — `assets/models/imported/furniture/gaming-table.*`,
  браузерная копия — `apps/client/public/assets/models/furniture/gaming-table.glb`.
- Ресурс `competition-table` опубликован в чанке c-2-2, с новым SHA-256 и
  byteSize. LocalArt не создаёт вторую копию стола вне ResourceLedger.
- Центр `(80,0,83)`, четыре стула по сторонам. Подтверждённая посадка,
  camera yaw и выход используют те же позиции, что и размещения стульев.
- UI показывает вместимость из конфигурации; демо-сценарии — 2/4 участника.
  Четвёртый виртуальный игрок остаётся гулять, когда пользователь и три бота
  заняли все места. NPC-преподаватели и София за стол не садятся.
- Прямоугольная коллизия стола учитывает поворот и размер модели, запас для
  персонажа — 0.25 м. Пути Софии и четырёх демо-игроков проходят по свободным
  проходам вокруг стола и стеллажей. После выхода бот возвращается по поиску пути.

Единый пример четырёх мест — `apps/client/mock-v2/public-config.json`,
`values.gameplay.competition.tables[0].seats`. Размещения этих же стульев —
`assets/world/reading-room-layout.json`. В обоих файлах нет пятого стула.
Четыре существующих seatId сохранены, `competition-seat-5` удалён из новой
расстановки. Ставки, вопросы, сроки, подсчёт и выплаты не менялись.

## Точная правка схем для владельца протокола

Машиночитаемый список замен:
`apps/client/mock-v2/four-seat-contract.patch.json`.
У каждой записи указаны исходный файл схемы, JSON Pointer и новое значение.
Заменяются только девять ограничений:

1. `gameplay-config`: competition.maxPlayers, const 5 → 4.
2. `gameplay-config`: tables[].seats, minItems/maxItems 5 → 4.
3. `competition`: максимум participants, occupiedSeats, answeredPlayerIds,
   scores и обеих форм payouts, 5 → 4.

Имена HTTP/WS команд и событий, обязательные поля, теги ответов, права,
идемпотентность, экономика, таймеры и правило ничьей остаются прежними.
Лимит подключений игровой комнаты (`session.maxPlayers`) — отдельное
ограничение; он не становится четырьмя автоматически.

## Изоляция проекта

`mock-v2/four-seat-contract.js` применяет изменения к **копиям** выпущенных
схем в отдельном экземпляре AJV. Его использует только LocalMockAdapter,
включая восстановление конфигурации и валидацию локальных событий.
Схемы не ослаблены: пятый участник/пятая выплата отклоняются этим профилем.

Внутри демо сохранены конверты базовой версии 2.0.0 для общих компонентов,
но это **не утверждение сетевой совместимости** четырёхместной конфигурации
с выпущенным 2.0.0. Mock не отправляет эти данные по HTTP/WebSocket.
`demo-mode.json` явно содержит `previewProfile: competition-four-seat-draft`
и `productionMultiplayer: false`; интерфейс помечен «Демо · 4 места».

В real build отсутствуют этот профиль и его валидатор. RealAdapter продолжает
принимать только выпущенную схему 2.0.0 с пятью местами и отклонит конфигурацию
на четыре места. Включать четыре места для Rust нужно после согласованного
релиза протокола; номер будущей версии здесь не назначен.

Черновой каталог сохранён отдельно:
`assets/world/catalog.four-seat-draft.server-only.json`. Каталог
`assets/world/catalog.server-only.json`, который читает текущий Rust,
сохранён прежним. `world:publish` теперь обновляет именно черновой каталог
и mock published.json; запуск или пересборка Rust не включает четыре места
случайно. Старые ресурсы с адресацией по хешу не удалены.

## Задачи backend-разработчика после согласования

- Выпустить новую версию схем/фикстур и обновить клиентскую сетевую валидацию
  согласованным релизом. Сохранить прежнюю версию для старых клиентов.
- Использовать четыре места из конфигурации. Пятую конкурентную попытку
  посадки отклонять атомарно до изменения activity или резерва ауры.
- Обновить positions/yaw/exitPosition, коллизии, конфигурацию и каталог
  ресурсов согласованно с новой worldRevision/effectiveTick.
- Закончить старые матчи на пяти местах либо отменить их с подтверждённым
  возвратом до замены расстановки. Не удалять занятое место активного матча.
- Проверить ready всех четырёх, изменение условий, выход, reconnect,
  отключение пятого seatId, выплаты четырём и ничью с возвратом всем.

соответствие четырёх стульев четырём местам, направление взгляда, свободные

возврат к маршруту. `verify-bundle.js`: отсутствие draft-профиля в real build.

`npm run check:release`: 82/82 теста, обе сборки и проверка их изоляции прошли.
Демо-interest занимает 195034 байта при бюджете 298843 байта (6.53% W).
Хеши/размеры и вместимость одного чанка проверены для обоих каталогов.
Последнюю браузерную QA завершить не удалось: инструмент управления Safari
потерял окно (`noWindowsAvailable`). Запись browser.json с ошибкой старта
не является успешной проверкой новой сцены; визуальную приёмку в браузере
нужно повторить. Нагрузочный замер GPU/FPS этой версии не подтверждён.
