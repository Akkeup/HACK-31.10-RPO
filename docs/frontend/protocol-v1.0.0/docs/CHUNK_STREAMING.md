# Пространственная выдача и кеш ≤10%

## Нормативная метрика

W = totalWorldBytes: сумма byteSize всех уникальных неизменяемых chunk JSON и всех уникальных транзитивных ресурсов активной worldRevision. Один SHA-256 с одинаковыми байтами учитывается один раз, даже если есть разные resourceId. JSON считается в точных UTF-8 байтах HTTP entity после Content-Encoding; сериализация не меняется после публикации. GLB/glTF, текстуры, анимации, collision data и зависимые бинарные файлы входят в W. Встроенные base64/data URI уже входят в байты контейнера и повторно не считаются. Внешние glTF URI должны быть только на ресурсы того же мира, перечисленные в interest; относительные неизвестные зависимости и внешние сетевые URL запрещены. Сервер разворачивает транзитивные зависимости до выдачи interest. Запрещено раздувать W дубликатами или неиспользуемыми фиктивными файлами ради бюджета.

B = floor(W / 10). C — множество уникальных hash ресурсов, удерживаемых клиентом: активные, неактивные, сырые ArrayBuffer, декодированные сцены/текстуры и GPU-ресурсы. R — множество зарезервированных загрузок, ещё не входящих в C. Обязательный инвариант на каждой операции: sum(byteSize(h), h∈C∪R) ≤ B. Для каждого hash должна существовать ровно одна запись учёта и один сетевой запрос. Счётчик не сбрасывается при пересоздании сцены. Нельзя освободить запись, пока есть ссылка на её Three.js geometry/material/texture, включая другой чанк.

Это логический объём уникального контента: несколько CPU/GPU представлений одного hash учитываются по его byteSize один раз, а не по физическому размеру видеопамяти. Дополнительно клиент ограничивает оценочную RAM+VRAM ресурсов мира 256 MiB, отдельным счётчиком, снижает pixelRatio/LOD и выгружает при давлении. Лимит 10% не означает 10% RAM, количества чанков или сетевого трафика. Контрольные сообщения, executable JS, базовые UI icons и login page не входят в W; они не могут скрыто содержать игровые модели/геометрию. Неизменяемый контент мира в них запрещён. Контрольные данные interest/snapshot/config удерживаются только в последней версии и ограничены сообщением ≤64 KiB (HTTP public config ≤64 KiB), их нельзя использовать как обход ресурсного бюджета. Полный серверный каталог запрещено пересылать клиенту.

## Манифест и интерес

GET /worlds/{id}/manifest возвращает только worldRevision, W, B, accounting и пределы файлов. Сервер проверяет B=floor(W/10). На сервере полный каталог хранит chunk координаты, hash, byteSize, зависимости, nav/collision данные; fixtures/catalog.server-only.json — его тестовый аналог. Клиент получает через world.interest только выделенный набор чанков и замыкание их зависимостей. requiredBytes равен сумме уникальных hash набора. Каждое множество interest MUST помещаться в B и лимит физической памяти на целевой машине. Необязательное расширение радиуса разрешено только при доступном бюджете; drawDistance не даёт право на загрузку дополнительных чанков.

Chunk координаты: x=floor(position.x/chunkSizeM), z=floor(position.z/chunkSizeM), включая отрицательные значения. Chunk local origin (x*size,0,z*size); позиции objects в wire всегда мировые. Пределы grid включительны; разрешённые чанки — activeChunkIds на сервере. chunkId независим от координат, соответствие задаёт каталог, нельзя выдумывать ID по URL. worldRevision фиксируется на всю комнату.

world.interest — полный набор, interestRevision растёт монотонно на игрока, начиная с 1 на каждом новом соединении. URL имеют hash и worldId. Авторизация ресурсов проверяет bearer user, его комнату, текущую worldRevision, X-Interest-Revision и принадлежность файла текущему interest. Несуществующий hash/чанк — 404; известный, но неразрешённый — 403 OUT_OF_INTEREST; старая revision — 409 STALE_INTEREST. Дополнительный обход полного каталога/скачивание мира на клиент отсутствует. Старые ресурсы могут оставаться в локальном LRU под B, но не дают новых прав скачивания.

## Алгоритм загрузки

1. Проверить revision и descriptors, суммировать размер уникального замыкания. Если requiredBytes>B, не начинать загрузку, показать RESOURCE_TOO_LARGE и попросить серверный комплект меньших чанков/LOD. Повтор одинакового запроса не исправляет контентную ошибку.
2. Закрепить уже имеющиеся hash нового набора. Отменить ненужные загрузки AbortController, освободив резерв только после завершения/очистки их буферов. Удалить неиспользуемые ресурсы по LRU с refcount=0; если нужно, сначала убрать старый активный чанк и показать экран загрузки.
3. Атомарно зарезервировать byteSize для каждого отсутствующего hash до fetch. Если суммы превышают B, выгрузить ещё или остановить загрузку. Одновременно не больше двух запросов. Content-Length не заменяет проверку фактически полученных байтов; для chunk/asset сервер отдаёт identity Content-Encoding, Caddy compression для этих путей отключена. Разрыв/лишние байты освобождают резерв после очистки.
4. Проверить фактический byte length, SHA-256 через crypto.subtle, JSON Schema для chunk, worldId/revision/chunkId и зависимости. Несоответствие — удалить буферы, не декодировать/не рендерить, показать INVALID_REQUEST и повторить не более одного раза.
5. Превратить reservation в resident запись, не увеличивая сумму. Декодировать, зарегистрировать все refcounts и оценку CPU/GPU. Послать world.ready с точным множеством hash текущего interest. Имена моделей/ассетов разрешаются только через текущий каталог, не через произвольные URL.
6. При уходе удалить Mesh из scene, остановить animation mixers, вызвать geometry.dispose(), material.dispose(), texture.dispose(), очистить ImageBitmap/ArrayBuffer/GLTF loader references. Общий ресурс освобождается только когда refcount=0; пока существует любая CPU/GPU ссылка, ресурс остаётся в C. Отчёт client.metrics раз/с.

Cache-Control:no-store на всех world-resource ответах и fetch cache:no-store. Не кешировать world paths через Service Worker, CacheStorage, IndexedDB или browser disk cache; это создаёт неучтённые копии. Управляемый in-memory LRU — единственный кеш v1. После logout/world change освободить все ресурсы и резервы. Клиент может переиспользовать C при reconnect только для той же worldRevision и совпадающих hash. На смене worldRevision сначала полностью освободить старую, затем принять новый W/B; смешение двух миров под двумя отдельными бюджетами запрещено.

## Фикстура

Тестовый мир содержит 100 маленьких чанков и одну общую валидную glTF-модель треугольника. Файлы компактно сериализованы с LF; изменение пробелов меняет hash/byteSize. Точные W/B/requiredBytes находятся в fixtures/http/manifest.json и interest.json. Все числа пересчитываются tools/validate.cjs из реальных байтов. Полный каталог нужен только mock/серверу. Данные демонстрируют формулу, а не доказывают, что реальная художественная сцена помещается в лимит.

Серверный publish должен отклонить сборку, где хотя бы обязательный single-chunk набор с зависимостями не помещается в B; решение — smaller chunks, lower LOD, разделение textures/GLB, а не обход лимита. Ошибка RESOURCE_TOO_LARGE — 409 при создании/подключении комнаты или server.error до выдачи interest. Сервер не может криптографически доказать, что браузер удалил память; выдача только interest и клиентский учёт являются механизмом соблюдения, телеметрия — наблюдением, не античит-гарантией.
