## Исправления клиента при проверке

Активный реестр содержит только 27 неизменённых официальных схем 2.0.0.
Схемы 1.x сохранены в архиве и подключаются отдельным legacy-модулем для
регрессионных тестов. Убраны старые DEV QA-входы из основного запуска.
В обеих production-сборках нет `/api/v1`, `discovery.v1` и идентификаторов
схем 1.x. Ответы используют tagged `answer`, восстановление — `submittedAnswer`.

HTTP-адаптер отклоняет старые и внешние маршруты до fetch; версия заголовка
фиксирована на `2.0.0`. Ticket валидируется со строгими `/api/v2/ws` и
`discovery.v2`. Нет downgrade и удаления неизвестных полей из ответов сервера.
Старая подсказка `/api/v1/auth/login` исправлена.

Устранено расхождение Vite/адаптера: **real по умолчанию**, mock выбирается
явно. В real нет демо-адаптера, закрытых демо-ответов и `demo/resources`.
Mock получает локальные ресурсы и явный `demo-mode.json` с версией 2.0.0.
Проверка сборок учитывает оба режима. Инструкции обновлены, старые помечены архивом.

LAN fallback UUID/SHA-256 вынесен в отдельные функции без глобальной подмены
Crypto. Прежний fallback UUID мог вызвать себя рекурсивно при присвоении
`crypto.randomUUID = safeRandomUUID`; SHA-подмена также игнорировала аргумент
алгоритма. Теперь используются явные вызовы, CSPRNG для UUID и SHA-256 для
проверки ресурсов, включая ArrayBuffer views с ненулевым offset.

Демо-кнопка страны больше не отправляет `demo-country-a` в real. Локальный
переход между кабинетами в real отклоняется до подмены координат: утверждённой
команды перехода нет. Mock-переходы сохранены. Для real нужны серверный
механизм и согласованный контракт, а не новый самодельный WS message.

## Блокирующие расхождения backend — по исходному коду

1. `apps/server/src/ws.rs:280–330`: нет обработки `quiz.start`, `quiz.answer`,
   `quiz.next`, `quiz.leave`, `quiz.resume`, `quiz.abandon`. Команды клиента
   останутся без ожидаемого подтверждения. Нужен полный lifecycle v2,
   включая сохранение suspended и восстановление того же вопроса/feedback.
2. `apps/server/src/http.rs:543–546`: все GET с `/education/attempts`
   возвращают `[]`. Список должен быть `{ "attempts": [] }`, собственная
   попытка — объект attempt по `education.schema.json`. Сейчас строгая
   проверка восстановления попыток отвергает ответ.
3. `apps/server/src/ws.rs:672–679`: `competition.answer.accepted` содержит
   лишний `optionId`. В v2 допустимы `matchId`, `questionId`, `answer`,
   `acceptedAt`; `additionalProperties: false` отвергает это событие.
4. `apps/server/src/competition.rs:838`: ownRecovery содержит лишний
   `selectedOptionId`. В v2 разрешены только `state`, `submittedAnswer`,
   `answerAccepted`. Восстановление матча будет отвергнуто валидатором.

Дополнительно сервер хранит ответы соревнования как `current_option_id` и
при восстановлении создаёт `kind: single_choice` независимо от исходного
типа. Одного удаления лишних полей недостаточно для поддержки numeric,
short_text, explanation и flag_country: нужны хранение исходного tagged
answer и проверка по виду вопроса. Иначе письменный ответ после reconnect
будет иметь неверный kind.

`main.rs`, `auth.rs`, HTTP-router и fallback spatial по-прежнему содержат
поддержку 1.x. Само наличие старого маршрута/внутреннего alias не доказывает
невалидность v2-ответа, но сервер не является v2-only. В `docs/backend`
остались инструкции `/api/v1` и `discovery.v1`; их должен обновить владелец backend.

  кастомные модели.

  После изменения исходников сначала пересоберите клиент; root launcher не изменялся.

полная совместимость всего проекта с 2.0.0 пока блокируется серверной частью.
