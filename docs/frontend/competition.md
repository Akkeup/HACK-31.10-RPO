# Соревновательный стол — Protocol 1.1.0

Клиент использует переданный `Discovery-Protocol-v1.1.0.zip`, HTTP `/api/v1`, WS subprotocol `discovery.v1`, точную версию `1.1.0` и заголовок `X-Discovery-Protocol`. Rust, БД и инфраструктура не менялись.

## Как пройти

1. `cd apps/client && npm run dev`, открыть адрес Vite. Нужны заранее установленные npm-зависимости; внешнего интернета во время игры не требуется.
2. Стол рядом со стартом, к югу от фонтана. Щёлкнуть в мире для обзора, WASD — движение. Навести взгляд на стол в радиусе конфигурации, нажать E. Подсказка содержит занятость, тему, ставку и статус.
3. Сервер выбирает свободное место. Камера переходит к сидящему положению только по координатам/activity из snapshot. Свой GLB скрыт, остальные игроки видимы в сидячей позе даже с выключенными анимациями. NPC не используют места соревнования.
4. В лобби создатель задаёт одну из трёх тем и целую ставку. Каждый подтверждает её кнопкой «Подтвердить ставку и готовность». Доступный баланс, резерв и банк приходят с сервера. Смена условий освобождает резерв и снимает готовность. Старт — только создателю при 2–5 подключённых готовых игроках, сервер перепроверяет.
5. Вопросы с четырьмя вариантами, deadline, подтверждение собственного ответа и закрытый результат отображаются в панели поверх первого лица. Повторная отправка блокируется сразу, принятый ответ — только по ACK. До закрытия чужие варианты не раскрываются.
6. Победитель/ничья, выплаты/возврат и кошелёк показываются по событиям/API. До подтверждения расчёта выигрыш не прибавляется. Новый матч требует нового явного подтверждения.
7. **F — встать** (также кнопка в шапке панели, всегда видна без прокрутки). Во время матча F открывает подтверждение, а не отправляет выход сразу. E открывает панель. Камера сидящего игрока в demo расположена на высоте 1,51 м — у центра головы сидящей модели. Встать до старта — освобождение резерва; во время матча — отдельное предупреждение о пропущенных вопросах и сохранении ставки в банке. Esc/«Свернуть» только прячут панель. E открывает её снова. После reconnect клиент читает фактическое состояние, не повторяет ставку или старт.

## Файлы

- `src/gameplay/competition.js`: серверное состояние и последовательность восстановления; без расчётов баллов/денег.
- `src/ui/competition-ui.js`: лобби, вопросы, закрытые результаты, финал, предупреждение о выходе.
- `src/network/adapters.js`: один транспорт для mock/real, requestId, обработка ошибок, HTTP recovery и server clock.
- `mock/competition.js`: локальная серверная симуляция резервов/escrow/раундов/settlement/idempotency, Node only.
- `mock/education.js`, `src/ui/education-ui.js`: обязательные lesson/quiz события новой версии для существующих зон NPC.
- `assets/world/gameplay.json`: положение стола, пять посадочных/выходных transforms, расположение учебных станций и firstPersonDefaults. Серверные правила не являются локальными настройками пользователя.
- `scripts/publish-demo-world.js`: публикация общего стола, стульев и учебных стульев в обычные чанки/GLB с пересчётом SHA/W/B.

Бюджет опубликованного demo: `W=3 079 510`, `B=307 951` байт. Ограничение `C ∪ R ≤ B` действует также при загрузке/смене чанков и на все GLB мебели/персонажей. Динамические подписи — UI, художественная мебель в JS не создаётся. Материалы/геометрия общие, инстансы освобождаются через прежний ResourceLedger.

## Mock-сценарии

По умолчанию при посадке игрока присоединяется один синтетический **игрок**, не NPC. Он явно подтверждает условия на стороне mock и отвечает через ту же серверную машину состояний.

```sh
DISCOVERY_MOCK_PLAYERS=5 npm run dev
```

Это переменная Node mock, в реальном клиенте её нет. Начисление начальной ауры происходит при создании демо-аккаунта, а не при каждом login. Все demo-данные эфемерны и очищаются при перезапуске процесса. Mock не заменяет транзакции/персистентность/операторские средства настоящего backend.

`npm test` проверяет создание лобби, пять мест и отказ шестому, смену владельца, CAS/idempotency, сброс резервов, нехватку ауры, закрытие по сроку, приватность ответов, победу/поражение/ничью, отмену/возврат, отсутствие повторной выплаты, reconnect и освобождение мест после grace.

`npm run test:integration` использует настоящий локальный HTTP/WS и браузерный DiscoveryAdapter: полная загрузка GLB/interest, посадка, кошелёк, ready/start/answer, принудительный обрыв WS и восстановление ответа без повторного списания, отмена/возврат, новый матч, обязательные lesson/quiz и авторизованные ETag-настройки.

В DEV `/?qa` проходит через DOM-кнопки лобби и все пять вопросов, reconnect, финал, новый матч/предупреждение выхода, учебные зоны и переход чанка. Сохраняет результаты в игнорируемый `apps/client/test-results/browser.json`; `/tests/responsive.html` проверяет 390×844. Стенд рассчитан на чистый mock: перезапустить Vite перед повтором, не менять файлы во время прогона. QA не включается в production build и не работает с real adapter.

## Реальный сервер

`VITE_TRANSPORT=real`, `DISCOVERY_BACKEND_URL=http://127.0.0.1:8080` в `.env.local`, перезапуск Vite. В production раздать `dist` вместе с API одного доверенного origin. Нужен backend с точной поддержкой 1.1.0: несовпадение версии останавливает вход. Новых несовместимых игровых сообщений и локального пересчёта баланса нет.

Сборка/схемы/mock не подтверждают работоспособность Rust, TLS или производительность на ноутбуках всех участников. Это проверяется после предоставления соответствующего сервера и машин. Vite сообщает о размере vendor chunk Three.js свыше 500 КБ; он отделён от приложения и входит в кеш оболочки, не в ресурсный кеш мира.
